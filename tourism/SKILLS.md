# مهارات وتعديلات تعلمناها من بناء الموقع

ملف مرجعي يجمع الدروس والأخطاء والحلول يلي طلعت معنا وإحنا عم نبني ونطوّر موقع "ساحة سياحة" (index/place/add-place/regions/cafes/restaurants/landmarks/gardens/shops). الهدف إنه أي شغل جديد على الموقع يمشي على نفس القواعد هاي من البداية، بدل ما نكتشف نفس المشاكل من جديد.

---

## 1. بناء موقع تفاعلي متجاوب مع كل الشاشات

### القاعدة العامة
كل صفحة/قسم لازم يشتغل صح على 3 مستويات عرض على الأقل، مبنية على نقاط توقف (breakpoints) واضحة:
- **> 820px** — لابتوب/ديسكتوب (التصميم الأساسي)
- **≤ 820px** — الجوال والتابلت (`@media (max-width:820px)`)
- **≤ 400px / ≤ 360px** — الجوالات الضيقة جداً (iPhone SE، أندرويد قديم) — نقاط توقف إضافية أضيق لما التصميم العادي بينكسر

### القرار الأهم يلي تعلمناه
**لا تفترض إنه إذا الشي شغال عند 375px رح يشتغل من 400 لـ820 كمان.** أكتر من مرة صلحنا مشكلة عند مقاس معين واكتشفنا لاحقاً إنها لسا موجودة بمدى تاني (مثلاً: صورة `.t-cta` كانت متصلحة عند 320-400 بس منكسرة من 401-820 لأنه ما كان في قاعدة عامة تغطي المدى كامل؛ وحدة تبويبات الفوتر كانت تمام عند 375 بس فيها overflow عند 320 و582). **الحل: لازم نفحص المدى كامل (320، 360، 400، 401، 500، 700، 820، 821+) مش بس نقطة وحدة، وبعد أي تعديل نعيد الفحص عالمدى كامل مش بس النقطة يلي كانت فيها المشكلة.**

### خطوات عملية لأي عنصر جديد
1. صمم العنصر أول شي عالمقاس الكبير (لابتوب) لحاله.
2. ضيف `@media (max-width:820px)` وحوّل الأحجام الثابتة لنسبية (شوف القسم 2).
3. جرب عند 375px و320px و819px تحديداً (حواف المدى).
4. إذا لقيت انكسار بمدى ضيق بس، ضيف نقطة توقف أضيق (400 أو 360) بدل ما تفرض حل واحد يغطي كل شي.

## 2. استخدام وحدات نسبية (`vw` / `%` / `em` / `vh`) بدل البكسل الثابت

### ليش
أي حجم ثابت بالبكسل (`width:24px`) ما بيتقلص مع الشاشة. لما تصغر الشاشة، العنصر يضل بنفس الحجم ويصير نسبته للمحتوى حواليه غلط (بيطلع كبير/بيخرب التخطيط).

### الحل المستخدم بكل الموقع
كل الأيقونات والعناصر الزخرفية (اللوجو، الأفاتار، أيقونات الفوتر، سهم "عرض الكل"، قلب المفضلة، أيقونة زر CTA...) تم تحويلها من `px` ثابت لوحدة نسبية **مختارة حسب طبيعة العنصر**، مش وحدة واحدة للكل:

| الوحدة | الأنسب لـ | مثال من الموقع |
|---|---|---|
| `vw` | عناصر تتقلص مع عرض الشاشة نفسها (لوجو، أفاتار، أيقونات مستقلة) | `.t-avatar { width:8vw; height:8vw; }` |
| `%` | عنصر جوه container له حجم محدد فعلياً (أيقونة SVG جوا دائرة) | `.t-footer-social a svg { width:45%; height:45%; }` |
| `em` | عنصر لازم يتبع حجم الخط المجاور له مباشرة (سهم جنب نص) | `.t-section-head a .chev { width:1.2em; height:1.2em; }` |
| `vh` | ارتفاعات مرتبطة بطول الشاشة مش عرضها (خلفية hero) | `.t-hero { height:37vh; }` |
| `clamp(min, vw, max)` | أي عنصر لازم يتقلص **وكمان** ما يكبر أكتر من حد معقول | `.t-cta-btn { font-size:clamp(9px, 2.5vw, 12.5px); }` |

### خطأ حقيقي وقعنا فيه: `vw` بدون سقف
حطينا `font-size: 2.5vw` لزر CTA بدون حد أقصى — عند الشاشات الأعرض (700px مثلاً) الخط كبر لحد 17.5px وصار يتداخل مع النص فوقه. **الدرس: أي `vw` عالنص أو زر لازم يكون جوا `clamp()` بحد أدنى وأقصى، مش `vw` لحاله.**

### قاعدة سريعة
- لو الوحدة الحالية px والعنصر المفروض يتقلص مع الشاشة → بدّلها `vw` أو `%` أو `em` (حسب الجدول فوق).
- لو بدّلتها `vw` بدون سقف → تأكد فيه داعي فعلي لعدم وجود حد أقصى (نادراً)، وإلا لفّها بـ`clamp()`.

## 3. انكسار النص العربي المكوّن من كلمتين

### المشكلة
عناصر زي "من نحن" أو أسماء الروابط بالفوتر، لما تضيق المساحة، النص بينكسر لسطرين جوا نفس العنصر (كل كلمة بسطر) بدل ما ينضغط العنصر نفسه أو يعمل scroll. هيك بيطلع شكل مكسور وغير احترافي.

### السبب
العناصر (`<a>`) داخل حاوية `flex` ما كان عندها `white-space: nowrap`، فلما الـflex يحاول يضغط العنصر، النص جواته يرجع لسلوكه الطبيعي (`white-space: normal`) وينكسر بدل ما يضل بسطر واحد.

### الحل
```css
.t-footer-links a {
  white-space: nowrap; /* منع انكسار الكلمتين لسطرين */
}
```
**لازم يترافق مع حل لمشكلة المساحة نفسها** (لأنه `nowrap` وحده بيمنع الانكسار بس ممكن يسبب overflow حقيقي إذا المساحة ضيقة فعلاً). الحلول المتاحة بالترتيب:
1. تصغير الخط/المسافات (`font-size`, `gap`) بوحدات نسبية لحد معين.
2. إذا التصغير وصل لحد غير مقروء (أصغر من ~9-10px) **بلاش تكمل تصغير** — بدل هيك خلي الصف يعمل `overflow-x:auto` (سكرول أفقي داخلي للصف نفسه بس، مش للصفحة كاملة).

```css
.t-footer-top-inner {
  flex-wrap: nowrap;
  overflow-x: auto;             /* سكرول للصف لحاله لو ما كفت المساحة */
  -webkit-overflow-scrolling: touch;
  scrollbar-width: none;         /* إخفاء شريط السكرول البصري */
}
.t-footer-top-inner::-webkit-scrollbar { display: none; }
```

### قاعدة عامة
أي نص عربي مكوّن من كلمتين أو أكتر جوا عنصر flex قابل للانضغاط → حط `white-space:nowrap` من البداية، وفكر بمشكلة المساحة كخطوة منفصلة (تصغير أو سكرول)، مش بس نوّة تكبير/تصغير الخط.

## 4. الأخطاء الحقيقية يلي صلحناها وأسبابها

### 4.1 نسبة مئوية (%) بترجع "auto" لو الأب مالوش ارتفاع محدد
**المشكلة:** حطينا `height: 100%` على عنصر ابن (مثلاً تبويبات `.t-cat` جوا `.t-cats-group`)، وما اشتغلت.
**السبب:** الأب (`.t-cats-group`) كان ارتفاعه "auto" (بيتحدد من حجم أولاده). نسبة الارتفاع بتحتاج الأب يكون عنده ارتفاع **محدد فعلياً** (px، أو نسبة محسوبة من جد له ارتفاع محدد)، وإلا المتصفح بيتجاهلها تماماً ويتصرف كإنها "auto".
**الحل:** قبل ما تحط `height:100%` أو `width:100%` على أي عنصر، تأكد الأب المباشر (مو أي جد أبعد) عنده حجم محدد (px، أو `flex:1` جوا flex container بحجم معروف، أو نسبة صحيحة من جد محدد).
**فخ إضافي:** حتى لو الأب أصبح محدد، لسا لازم تتأكد إنه فعلاً **الأب المباشر** (parent) مش أي جد (grandparent) — النسبة بتتحسب بس من أقرب أب، مش من أي حاوية أبعد.

### 4.2 `min-width:auto` الافتراضي بيمنع عناصر flex من الانضغاط تحت حجم محتواها
**المشكلة:** حطينا `width:100%` على تبويبات جوا مجموعة flex، وتوقعنا تتقاسم المساحة بالتساوي — بس ضلت عالقة عند حجم أكبر من المتاح.
**السبب:** عناصر flex افتراضياً `min-width:auto`، يعني المتصفح رافض يصغّرها تحت حجم محتواها الطبيعي حتى لو طلبت منها تنضغط.
**الحل:** ضيف `min-width:0` (أو `min-height:0` بحالة عمود) عشان تسمح للعنصر ينضغط فعلياً.

### 4.3 عنصر `<img>` (replaced element) بيتصرف مختلف مع `height:100%` جوا flex
**المشكلة:** حطينا `width:100%; height:100%` على `<img>` جوا حاوية flex `align-items:center`، وطلع ارتفاعها أصغر من المتوقع (مش مطابق لأبوها تماماً).
**السبب:** الصور "عناصر مستبدلة" (replaced elements) عندها خوارزمية حجم خاصة بتحاول تحافظ على نسبة العرض للارتفاع الطبيعية للصورة، حتى لو الأبعاد الاثنين محددة بالنسبة — بتتعارض مع `object-fit`/flex أحياناً.
**الحل الأضمن:** استخدم `position:absolute; inset:0;` على الصورة (بدل الاعتماد على flex/height:100%)، مع `.parent { position:relative; }`، و`object-fit:cover` — هيك الصورة تاخذ حجم أبوها بالظبط بدون ما تتأثر بخوارزميات flex.

### 4.4 خطأ بنية HTML (وسم إغلاق `</div>` بالمكان الغلط) — أخطر خطأ صار معنا
**المشكلة:** `<div class="t-cats-wrap">` انفتحت وما انسكرت غير بعد ~140 سطر (بعد قسمين بطاقات وقسم الـCTA كامل) بدل ما تنسكر مباشرة بعد التبويبات. النتيجة كانت غير مرئية بصرياً (لأنه خلفية `.t-cats-wrap` بيضاء وما بانت الفروقات)، بس سببت تخبيط بمنطق CSS: `height:50%` كانت "تشتغل صح بالصدفة" لأنه الأب كان فعلياً كبير جداً (856px، لأنه بيحتوي محتوى مش المفروض يكون جواه)، وقت ما اكتشفنا الخطأ وصلحنا البنية، القيم يلي كانت "شغالة بالصدفة" احتاجت مراجعة كمان.
**كيف اكتشفناه:** المستخدم جرب يشيل خاصية CSS ولاحظ إنها أثرت رغم إنه تحليلنا النظري قال ما لازم تأثر — هاد التناقض كان الدليل على وجود مشكلة أعمق بالبنية، مش بس بالـCSS.
**الدرس:** لو نتيجة تجربة عملية تناقض التحليل النظري لـCSS، **صدّق التجربة وشك ببنية الـHTML نفسها** (وسم ناقص، وسم بمكان غلط) قبل ما تلوم خصائص الـCSS. افحص التعشيش (`element.contains(otherElement)` أو عدد children لعنصر body) بدل ما تفترض البنية صحيحة.

### 4.5 `fetch()` لملف JSON محلي بيفشل لو الصفحة متفتحة كملف (`file://`)
**المشكلة:** صفحة كانت تجيب بياناتها عبر `fetch('data.json')`، اشتغلت تمام لما فحصناها عبر سيرفر محلي، بس المستخدم فتح الملف مباشرة (دبل كليك) ولقى بس جزء من البيانات (fallback).
**السبب:** المتصفحات بتمنع `fetch`/`XHR` لملفات محلية لأسباب أمنية (CORS) — بيشتغل بس لو الصفحة مخدومة عبر HTTP (سيرفر حقيقي أو محلي).
**الحل:** لأي صفحة prototype لازم تشتغل بمجرد فتحها كملف، **ضمّن البيانات مباشرة جوا `<script>` كمتغير JS** بدل `fetch()` لملف خارجي. إذا البيانات كبيرة أو مشتركة بين صفحات متعددة، هذا القيد لازم يوخذ بعين الاعتبار من البداية.

### 4.6 وحدة `vw`/`%` بترجع أرقام مضلِّلة لو الشك بمرجعية القياس نفسها
**المشكلة:** إحنا فاحصين مقاسات بأداة اختبار، طلعت أرقام `window.innerWidth` غير متطابقة مع المقاس الحقيقي المطلوب (فرق تابت ~49px بكل قياس).
**السبب:** خلل/مضاعفة بأداة الفحص نفسها (`devicePixelRatio` أو مساحة chrome داخلية بالأداة)، مش بالكود.
**الدرس:** لو رقم قياس واحد غريب وثابت الفرق بكل مرة، جرّب تتحقق منه بطريقة تانية (`visualViewport.width` بدل `window.innerWidth` مثلاً) قبل ما تفترض في خطأ بالـCSS.

### 4.7 صور بـ`loading="lazy"` ما بتظهر محمّلة بأدوات الفحص الآلي
**الملاحظة:** أكتر من مرة فحصنا `img.complete`/`naturalWidth` وطلعت `false`/`0` رغم إنه الصورة فعلياً موجودة وسليمة (تأكدنا عبر `fetch()` مباشر للملف نفسه رجع 200).
**السبب:** بيئة الفحص الآلي ما بتفعّل `IntersectionObserver` (اللي `loading="lazy"` بيعتمد عليه) بنفس طريقة متصفح حقيقي.
**الدرس:** لو الصورة "مش محمّلة" حسب الفحص الآلي بس الرابط شغال (`fetch` ترجع 200)، هذا مش خطأ حقيقي بالموقع — جرب تأكيد إضافي (إزالة `loading="lazy"` مؤقتاً بالفحص، أو `fetch` مباشر) قبل ما تفترض في مشكلة.

### 4.8 عدم تفعيل الوضع الداكن تلقائياً بدون زر تبديل فعلي
**المشكلة:** لون الخلفية والحدود كانوا يختلفوا بين متصفحين مختلفين لنفس الصفحة.
**السبب:** الكود كان فيه `@media (prefers-color-scheme:dark)` بيغيّر الألوان تلقائياً حسب إعداد نظام التشغيل — وبما إنه ما في زر تبديل فعلي بالموقع يتحكم بيه المستخدم، صار كل متصفح ياخذ ألوان مختلفة بدون أي تفاعل من المستخدم.
**الدرس:** ما تخلي الألوان تتبع إعداد النظام تلقائياً إلا إذا فيه فعلاً زر/تبديل بالموقع يشتغل مع هالمنطق. إذا مافي، خلي الألوان ثابتة (متغيرة بس عبر `data-theme` attribute صريح يتحكم فيه كود الموقع، مش تلقائي).

### 4.9 تعديل كلاس مشترك بـ`style.css` بيأثر على كل صفحة بتستخدمه — حتى لو الشغل الحالي على صفحة تانية
**المشكلة:** كنا شغالين على تصميم صفحات جديدة (فئات: مقاهي/مطاعم/معالم..)، وطلب المستخدم "ظل خفيف من كل الجهات" لتبويبات `.t-cats`. عدّلنا `box-shadow` لكلاس `.t-cats-wrap` بملف `style.css` المشترك — وبما إنه نفس الكلاس مستخدم بالصفحة الرئيسية (`index.html`) كمان، انعكس التعديل عليها تلقائياً رغم إنه محدا طلب لمس الرئيسية بهالخطوة.
**السبب:** `style.css` مشترك بين كل الصفحات. أي تعديل على كلاس موجود فيه (مش كلاس خاص بصفحة جديدة) بينطبق **على كل الصفحات يلي بتستخدم هيك الكلاس**، مش بس الصفحة يلي عم تشتغل عليها هلق.
**الدرس (مهم لشغلنا دايماً):**
- **افصل بين الأعمال** — لما تخلص شغل على صفحة/ميزة وتنتقل لشغل جديد، ما ترجع تلمس نفس الكلاسات/الملفات المشتركة يلي كانت خاصة بالشغل القديم إلا إذا المستخدم صراحة طلب هيك.
- **قبل ما تعدّل كلاس بملف مشترك (`style.css`)، افحص وين هو مستخدم كمان** (`grep` عالكلاس بكل ملفات الـHTML) — إذا مستخدم بصفحات تانية خلصنا شغلها، **اعمل كلاس جديد خاص بالصفحة الجديدة** بدل ما تعدّل الكلاس القديم المشترك.
- إذا لازم تعديل مشترك فعلاً (نية واضحة إنه ينطبق بكل مكان)، وضّح هيك للمستخدم بشكل صريح قبل ما تسوّيه، مش بعده.

## 5. منهجية الفحص (كيف نتأكد إنه الشي شغال فعلاً)

- **اعتمد على قياسات JS حقيقية** (`getBoundingClientRect`, `scrollWidth`, `getComputedStyle`) بدل الاعتماد بس على وصف بصري أو لقطة شاشة — لقطات الشاشة بهالبيئة كانت تفشل أو تطلع static snapshot مو حقيقي.
- **افحص تقاطع/تداخل العناصر برمجياً**، مش بالعين:
  ```js
  function overlap(a, b) {
    return !(a.right<=b.left || a.left>=b.right) && !(a.bottom<=b.top || a.top>=b.bottom);
  }
  ```
- **افحص الصفحة كاملة مش بس العنصر يلي عدّلته** — أكتر من إصلاح بهالمشروع كسر أو أظهر مشكلة بعنصر تاني (الفوتر، الأيقونات، الـCTA) لأنه القيم مبنية على نسب مشتركة.
- **بعد أي تعديل، أعد اختبار كل نقاط التوقف** (320 / 360 / 375 / 400 / 401 / 500 / 700 / 819 / 820 / 900) مش بس النقطة يلي كانت فيها المشكلة.

## 6. تعليمات عامة اتبعناها بكل الموقع

1. **الهيدر والفوتر (top/back) ثابتين بكل الصفحات** — أي صفحة جديدة تاخذهم نسخة طبق الأصل بدون تعديل.
2. **مكوّنات مشتركة (زي CTA "أضف مكان") لازم تتكرر بنفس الشكل بكل صفحة تحتاجها**، مش تتصمم من جديد كل مرة.
3. **أي بيانات/صور حقيقية** (أماكن، مناطق) لازم تكون من مصدر مرخّص فعلياً (Wikimedia Commons: CC BY / CC BY-SA / public domain) — ممنوع صور محمية بحقوق نشر حتى لو للعرض التجريبي.
4. **لو ما لقيت صورة حقيقية مخصصة لعنصر معيّن**، استخدم أقرب صورة حقيقية بديلة **وسجّل الاستبدال** (تعليق أو حقل ملاحظة) بدل ما تسكت عنه.
5. **قبل ما تحكم إنه "خلص كل شي تمام"**، افحص بنية الـHTML نفسها (توازن الوسوم، `body.children`) مش بس مظهر الصفحة — الخطأ الأخطر يلي واجهناه (القسم 4.4) كان بالبنية مش بالتنسيق.
6. **افصل دايماً بين الأعمال** — لما نخلص شغل على صفحة/ميزة وننتقل لشغل جديد، ما نرجع نلمس نفس الملفات/الكلاسات المشتركة يلي كانت خاصة بالشغل يلي خلصناه، إلا إذا طلب صريح. كل مهمة إلها نطاقها، وأي تعديل خارج النطاق المطلوب لازم يكون بقرار واعي (كلاس جديد مثلاً) مش أثر جانبي (شوف 4.9).
